# Sealedクラスとインターフェースの理解 - Javaの新機能

## 概要
Javaの「sealed」キーワードは、クラスやインターフェースの継承を制限する機能です。これにより、クラス階層を明確に制御し、意図しない拡張を防ぐことができます。Java 15でプレビュー機能として導入され、Java 17で正式に採用されました。

## ドキュメンテーション
### 目的
「sealed」は、特定のクラスやインターフェースを継承できるクラスを制限し、プログラムの設計と保守を容易にします。この機能によって、開発者はクラス階層の構造を明確にし、予測可能な動作を促進できます。

### 使用法
`sealed`キーワードは、クラスやインターフェースを定義する際に使用します。継承を許可するクラスは、`permits`キーワードを使用して指定します。これにより、どのクラスが特定のsealedクラスを拡張できるかを明示的に示すことができます。

### 詳細
- **シーリングされたクラス**: クラスの宣言時に`sealed`修飾子を使用します。
- **許可されたクラス**: `permits`キーワードを使用し、継承を許可するクラスをカンマ区切りで列挙します。
- **サブクラス**: `sealed`クラスを継承するクラスは、`final`、`sealed`、または`non-sealed`の修飾子を持つ必要があります。

### 例
以下は、sealedクラスの基本的な使用例です。

```java
// Sealedクラスの定義
public sealed class Shape permits Circle, Square {
    // ...
}

// Circleクラスの定義
public final class Circle extends Shape {
    // ...
}

// Squareクラスの定義
public final class Square extends Shape {
    // ...
}
```

この例では、`Shape`クラスは`Circle`と`Square`クラスのみに継承を許可しています。`Shape`を拡張する他のクラスは定義できません。

## 説明
### 一般的な落とし穴
- **未定義のサブクラス**: `sealed`クラスを継承するクラスは、必ず`permits`リストに含めなければなりません。未定義の場合はコンパイルエラーとなります。
- **修飾子の制限**: 継承するクラスは、`final`、`sealed`、または`non-sealed`のいずれかの修飾子を持つ必要があります。これにより、拡張の方法が制限されます。

### 注意点
- `sealed`クラスは、データの整合性と設計の明確さを保つために非常に有用ですが、使い方を誤ると可読性が損なわれることがあります。
- 既存のコードベースに`sealed`を導入する場合は、影響を十分に考慮する必要があります。

## 一文要約
Javaの「sealed」キーワードは、クラスやインターフェースの継承を制限し、設計の明確さと保守性を向上させる機能です。
