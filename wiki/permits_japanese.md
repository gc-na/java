# Javaの「permits」について

## 概要
Javaの「permits」キーワードは、シールドクラスとシールドインターフェースに関連する新機能であり、特にJava 17以降のバージョンで導入されました。この機能により、クラスの拡張性を制限することができ、より安全で明確な継承関係を構築することができます。

## ドキュメント
### 目的
「permits」キーワードは、シールドクラスとシールドインターフェースを定義する際に使用され、どのクラスがシールドクラスを拡張できるかを明示的に指定します。これにより、開発者は意図的に拡張可能なクラスを制限し、コードの整合性を保つことができます。

### 使用方法
シールドクラスまたはシールドインターフェースを定義する際に、「permits」キーワードを使用します。以下はその基本的な構文です。

```java
public sealed class Parent permits Child1, Child2 {
    // クラスの内容
}

public non-sealed class Child1 extends Parent {
    // クラスの内容
}

public final class Child2 extends Parent {
    // クラスの内容
}
```

上記のコード例では、`Parent`クラスは`Child1`と`Child2`の2つのクラスのみが拡張できることを示しています。

## 例
以下に「permits」の基本的な使用例を示します。

```java
// シールドクラスの定義
public sealed class Shape permits Circle, Square {
}

// 扩張可能なCircleクラス
public final class Circle extends Shape {
    // Circleの実装
}

// 扩張可能なSquareクラス
public final class Square extends Shape {
    // Squareの実装
}
```

上記の例では、`Shape`クラスは`Circle`と`Square`のみを許可しています。他のクラスはこのクラスを拡張できません。

## 説明
### 一般的な落とし穴
1. **拡張の制限**: シールドクラスを使う際には、意図的にどのクラスを許可するかを慎重に考える必要があります。許可するクラスを誤ると、将来的にプログラムの拡張性が失われる可能性があります。
2. **シールドの適用**: シールドクラスは他のクラスやインターフェースとの関係においても慎重に設計する必要があります。シールドクラスを使うことで、コードが複雑化する場合がありますので、設計段階でしっかりと検討してください。

### 注意点
- 「permits」を使用することで、クラスの設計が安全になりますが、すべての状況において有用ではありません。プロジェクトの要件に応じて適切に使用することが重要です。

## 一文要約
Javaの「permits」キーワードは、シールドクラスの拡張可能なクラスを制限するために使われ、より安全な継承関係を実現します。
