# غير مختوم (Non-Sealed) في جافا: كل ما تحتاج معرفته

## ملخص
"غير مختوم" (Non-Sealed) هو مصطلح في جافا يشير إلى نوع من أنواع الفئات (classes) التي يمكن أن تُورث منها فئات أخرى. تم تقديم هذه الميزة في جافا 17، وهي تسمح بتوسيع الفئات المختومة (sealed classes) بطريقة أكثر مرونة.

## الوثائق
### الغرض
تُستخدم خاصية "غير مختوم" للسماح للمطورين بتعريف فئات يمكن أن تُورث منها فئات أخرى، حتى لو كانت الفئة الأصلية مختومة. هذا يمكن أن يكون مفيدًا في حالات معينة حيث يحتاج المطورون إلى توسيع نطاق الفئات مع الحفاظ على بعض التحكم في الوراثة.

### الاستخدام
تُستخدم الكلمة المفتاحية `non-sealed` في تعريف الفئة لتمكين وراثتها. يجب أن تُستخدم مع فئة مختومة (sealed class) أو واجهة مختومة (sealed interface).

### التفاصيل
- **التعريف**: يتم تعريف الفئة غير المختومة باستخدام الكلمة المفتاحية `non-sealed` بعد الكلمة المفتاحية `class` أو `interface`.
- **القيود**: يمكن أن تُورث الفئات غير المختومة من فئات مختومة، ولكن لا يمكن تعريف فئة غير مختومة في فئة غير مختومة أخرى.

## الأمثلة
### مثال 1: تعريف فئة مختومة وغير مختومة
```java
sealed class Animal permits Dog, Cat {
    // محتويات الفئة
}

non-sealed class Dog extends Animal {
    // محتويات فئة الكلب
}

class Cat extends Animal {
    // محتويات فئة القطة
}
```

### مثال 2: استخدام فئة غير مختومة
```java
non-sealed class GoldenRetriever extends Dog {
    // محتويات فئة الكلب الذهبي
}
```

## الشرح
### pitfalls الشائعة
- **عدم استخدام non-sealed بشكل صحيح**: من المهم استخدام `non-sealed` فقط مع الفئات التي تُورث من فئات مختومة. إذا حاولت استخدامها مع فئة غير مختومة، سيؤدي ذلك إلى خطأ في الترجمة.
- **تجاوز التعريفات**: تأكد من أن الفئات التي تُرث من الفئات غير المختومة لا تتجاوز القيود المحددة للفئة الأصلية.

### ملاحظات إضافية
- تُعتبر الفئات غير المختومة طريقة جيدة للحفاظ على مرونة النظام مع الحفاظ على بعض القيود.
- يمكن أن تساعد هذه الميزة في تحسين التصميم الكلي للتطبيقات الكبيرة والمعقدة.

## ملخص جملة واحدة
"غير مختوم" (non-sealed) في جافا يتيح لك توسيع فئات مختومة بمرونة، مما يسهل إدارة الوراثة في التصميم البرمجي.
