# الحواجز في جافا: مفهوم "sealed" واستخداماته

## ملخص
تتيح خاصية "sealed" في جافا تحديد القيود على كيفية وراثة الصفوف، مما يساعد في تحسين التحكم في التصميم وأمان الكود.

## الوثائق
### الغرض
تُستخدم خاصية "sealed" في جافا لتحديد الصفوف (classes) أو الواجهات (interfaces) التي يمكن أن تُرث منها. الهدف هو توفير تحكم أكبر في تسلسل الوراثة وتقليل الأخطاء الناتجة عن وراثة غير مقصودة.

### الاستخدام
تُعرّف الصفوف "sealed" باستخدام الكلمة الرئيسية `sealed`، ويتعين على الصفوف أو الواجهات التي ترغب في وراثتها أن يتم تحديدها باستخدام الكلمة الرئيسية `permits`.

### التفاصيل
- يمكن استخدام "sealed" مع الصفوف والواجهات.
- يجب على الصف الذي يرث من صف "sealed" أن يكون إما `final` (غير قابل للتوريث) أو `sealed` أو `non-sealed`.
- يجب أن يتم تحديد جميع الصفوف المسموح بها باستخدام الكلمة الرئيسية `permits`.

## الأمثلة
### مثال 1: تعريف صف "sealed"
```java
public sealed class Vehicle permits Car, Truck {
    // محتويات الصف
}

public final class Car extends Vehicle {
    // محتويات الصف
}

public non-sealed class Truck extends Vehicle {
    // محتويات الصف
}
```
في هذا المثال، يتم تعريف الصف `Vehicle` كصف "sealed" يسمح فقط للصفين `Car` و`Truck` بالوراثة منه.

### مثال 2: محاولة وراثة غير مسموح بها
```java
public class Bike extends Vehicle { // ستظهر هنا خطأ في الترجمة
    // محتويات الصف
}
```
هذا المثال سيؤدي إلى خطأ في الترجمة لأن `Bike` ليس ضمن الصفوف المسموح بها.

## الشرح
### الأخطاء الشائعة
- **عدم تحديد جميع الصفوف المسموح بها**: يجب دوماً تضمين جميع الصفوف التي يمكن أن ترث من الصف "sealed" باستخدام الكلمة الرئيسية `permits`.
- **محاولة وراثة صف غير مسموح به**: إذا حاولت وراثة صف "sealed" دون أن تُدرج الصف في قائمة `permits`، ستظهر لك أخطاء في الترجمة.

### ملاحظات إضافية
تساعد خاصية "sealed" المطورين في بناء هياكل قائمة على الوراثة بطريقة أكثر أمانًا، مما يسمح بتقليل الأخطاء وزيادة وضوح الكود.

## ملخص من سطر واحد
تُستخدم خاصية "sealed" في جافا لتحديد القيود على وراثة الصفوف، مما يعزز أمان الكود وتصميمه.
